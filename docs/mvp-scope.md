# c1oser.dev MVP 범위

- 상태: 범위 확정 (2026-09-30)
- 함께 읽을 문서: [기능 명세서](functional-spec.md). 이 문서의 ID는 기능 명세서의 요구사항 ID다.
- 5절의 백엔드 설계는 [DB 설계](erd.md)와 [API 명세서](api-spec.md)로 구체화했다. 둘이 다르면 그 문서들을 따른다.

## 1. MVP가 검증할 것

**"글은 파일, 분류는 폴더, 이동은 명령어"라는 방식으로 혼자 글을 쓰고, 남의 글을 찾아 읽을 수 있는가.**

이 질문에 답하는 데 필요한 것만 넣었다. 기준은 세 가지다.

1. 가입해서 폴더를 만들고 글을 쓰고 고치고 지우는 흐름이 끊기지 않는다.
2. 다른 사람의 공개 글을 찾아서 읽을 수 있다.
3. 위 두 가지를 명령어로도, 마우스로도 할 수 있다.

답글, 구독, 알림, 그래프는 시안의 비중이 크지만 위 질문에 답하는 데는 필요하지 않아서 뒤로 미뤘다.

## 2. 들어가는 것 (P0)

| 영역 | 기능 | 요구사항 ID |
|---|---|---|
| 인증 | 이메일 회원가입, 로그인, 로그인 유지, 로그아웃, 접근 제어, 약관 페이지 | AUTH-01~06 |
| 셸 | 공통 레이아웃, 명령 입력, 마우스 동등성, 명령 이력, Tab 자동완성, 오류 출력, 홈 | SH-01~07 |
| 폴더 | 만들기, 보기, 정렬, 지우기, 왼쪽 트리, 빈 폴더 화면 | DIR-01~06 |
| 글 | 만들기, 읽기, 마크다운 렌더, 편집기, 수정, 이동·이름 변경, 공개 범위(644, 600), 삭제, 휴지통 | POST-01~09 |
| 태그 | 달기, 태그별 글 목록 | TAG-01~02 |
| 검색 | 내용 검색, 이름 검색, 범위(전체, 내 글) | SRCH-01~03 |
| 사람 | 사람 목록, 사람 찾기, 다른 사람 블로그 | USER-01~03 |
| 마이페이지 | 내 정보, 프로필 수정 | ME-01~02 |
| 도움말·오류 | 도움말, 없는 경로 | HELP-01, ERR-01 |

요구사항은 40개이고, 명령어는 기능 명세서 5절 표의 P0 17줄이다.

화면으로 보면 시안 16개 중 15개가 들어간다. 빠지는 화면은 알림함(16)이고, 들어가는 화면도 오른쪽 패널의 그래프, 답글, 링크 영역은 비워 둔다.

### P2 — 그 이후

그래프(LINK-03, DIR-09, ME-06), 구독 확장(`watch`, TAG-04, SRCH-08, USER-09), 파이프·리다이렉트와 alias(SH-11~12, SRCH-07), 가져오기·내보내기(ME-07~08), 변경 비교(POST-16), `ln -s`(POST-17), 메일 알림(NOTI-06, AUTH-10), 겹치는 사람(USER-07~08).

## 4. 완료 기준

아래 시나리오가 처음부터 끝까지 명령어로, 그리고 마우스로 각각 통과하면 MVP가 끝난 것이다.

1. 게스트가 랜딩과 `/help`를 본다. 다른 주소를 열면 로그인 화면으로 간다.
2. 약관에 동의하고 가입한 뒤 로그인하면 홈이 나온다.
3. `mkdir python` → `cd python` → `touch pointer.md`로 글을 쓰고 태그를 달아 저장한다.
4. `cat pointer.md`로 읽는다. 코드 블록과 인용이 렌더된다.
5. `vi pointer.md`로 고치고, `mv pointer.md ptr.md`로 이름을 바꾼다.
6. `chmod 600 ptr.md`로 비공개로 바꾼다. 다른 회원이 그 폴더를 열면 빈 폴더로 보이고, 글 주소를 직접 열면 "없는 경로" 화면이 나온다. `grep`과 `find` 결과에도 나오지 않는다.
7. 다른 회원이 `ls /users` → `cd /users/{아이디}`로 들어가 공개 글을 읽는다. 그 글을 고치거나 지울 수는 없다.
8. `grep 포인터`가 일치한 줄을 보여 주고, `find pointer`가 파일을 찾는다.
9. `rm ptr.md`는 파일 이름을 입력해야 실행된다. `u`로 되돌리고, 다시 지운 뒤 `~/.trash`에서 복구한다.
10. 글이 남은 폴더에 `rmdir`을 하면 거절된다.
11. `cat pointr.md` 같은 오타는 "없는 경로" 화면으로 간다.
12. `logout` 후에는 글 주소가 다시 로그인으로 간다.

## 5. 백엔드 설계 초안

이 저장소는 REST API 서버다. 지금은 Spring Boot 4.1.1(Java 21)에 `webmvc`만 들어 있다.

### 전제

- 명령어 해석은 프런트가 한다. 프런트가 `cd python`을 읽고 API를 부른다. 서버에는 명령어 개념이 없다.
- 서버는 경로를 실제 폴더·글로 바꿔 주는 조회 API를 제공한다.

### 데이터 모델

자세한 설계는 [DB 설계](erd.md)에 있다. 요약하면 다음과 같다.

| 테이블 | 담는 것 |
|---|---|
| `users` | 아이디, 이메일, 비밀번호 해시, 표시 이름, 한 줄 소개, 연락처, 가입일, 로그인 실패 횟수 |
| `refresh_tokens` | 리프레시 토큰의 해시. 로그인 한 번마다 한 가족 |
| `folders` | 소유자, 부모 폴더, 이름, 홈 기준 경로. 사용자마다 홈 폴더가 하나 있다 |
| `posts` | 소유자, 폴더, 파일 이름, 제목, 본문(마크다운), 공개 범위, 버전, 만든 날, 고친 날, 지운 날 |
| `tags`, `post_tags` | 태그 이름표와 글에 붙은 태그 |

- `(부모 폴더, 이름)`과 살아 있는 글의 `(폴더, 파일 이름)`은 각각 고유하다.
- 휴지통은 글의 "지운 날"로 표현한다. 지운 지 30일이 넘은 글은 예약 작업이 완전히 지운다.

### API

자세한 명세는 [API 명세서](api-spec.md)에 있다. 기본 경로는 `/api/v1`이다.

| 영역 | 엔드포인트 |
|---|---|
| 인증 | `POST /auth/signup`, `GET /auth/availability`, `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout` |
| 나 | `GET /me`, `PUT /me/profile`, `GET /me/summary` |
| 사람 | `GET /users`, `GET /users/{username}`, `GET /users/{username}/posts`, `GET /users/{username}/tree` |
| 폴더·경로 | `POST /folders`, `GET /folders/{id}`, `DELETE /folders/{id}`, `GET /fs?path=` |
| 글 | `POST /posts`, `GET /posts/{id}`, `PATCH /posts/{id}`, `DELETE /posts/{id}` (휴지통으로) |
| 휴지통 | `GET /trash`, `POST /trash/{id}/restore`, `DELETE /trash/{id}` (완전 삭제) |
| 검색·태그 | `GET /search/content`, `GET /search/names`, `GET /tags`, `GET /tags/{name}/posts` |

### 작업 순서

| 단계 | 내용 | 끝나면 통과하는 시나리오 |
|---|---|---|
| 1 | DB·보안 설정, 회원가입(홈 폴더 포함), 로그인, 토큰 갱신, 로그아웃, 접근 제어, 홈 요약 | 1, 2, 12 |
| 2 | 폴더, 글 CRUD, 경로 조회, 트리, 태그 | 3, 4, 5, 10, 11 |
| 3 | 공개 범위, 사람 목록, 다른 사람 블로그 | 6, 7 |
| 4 | 휴지통, 자동 비우기 | 9 |
| 5 | 검색 | 8 |

| 7 | 모바일 | MVP는 데스크톱만 | 시안이 1440×900뿐이다 |
